# SCREEN 현장 영상 훈련 구현 계획

2026-11-18 U31/U32. 기존 plan.md를 바꾸지 않고 새 screen/ 웹 프로그램으로 구현한다.

## 요구와 판단

- S01: 큰 실시간 3D 현장·작은 우측 상황 메시지·전체화면·일시정지/재개.
- S02: A=건물 전면. 위에서 본 시계방향 A→B→C→D. 로컬 좌표 A=+Z/B=-X/C=-Z/D=+X. 전면 방위각으로 현장 방향을 회전한다. 지휘관 낮은 시점/전체/상공/4방면과 회전·확대.
- S03: 자체 제작 가상 재질·입체 건물/창호/도로·주변 건물·빛/그림자·움직이는 연기/불꽃/방수/경광등. 실사 사진·실제 피해 예측으로 표시하지 않는다.
- S04: 시나리오별 건물·화재 위치/층/방면·요구조자·소방차/고가차/구급차·지휘대·대원·소화전·통제선을 사전 배치하고 JSON 저장/가져오기.
- S05: 시나리오 사건은 첫 사건≥60초, 모든 간격≥60초. 기본 자동 진행·선택 승인 진행, 정지/재개/종료. 미래 사건은 공용 응답/번들에 넣지 않는다.
- S06: 서버 시계/원자 메시지+상태+이력·버전/멱등성·복구. 재시작은 정지 상태로 복구하고 중단 시간을 몰아서 사건으로 공개하지 않는다.
- S07: 주요 화재 상황을 범주별 JSON 카탈로그로 제공. 불완전/확장 가능·독자 작성 가상 멘트·출처는 분류 참고. 기관 SOP·정답·과학 예측으로 주장하지 않는다.
- S08: 진행자 설정/시나리오 검토/회의 기록은 권한 분리. 공용화면에는 현재 장면과 공개된 메시지만 전송한다. 화면만 숨기는 권한 검사를 사용하지 않는다.
- S09: 주소/좌표·실제/근사/가상·출처/권리/정확도, 실제 자료는 승인 자산 경계. 실제 전국 모든 건물의 형상·실사 텍스처가 존재한다고 가정하지 않는다.
- S10: 전국 건물 선택·실사 적용은 공급자 범위/이용권/키·승인된 모델/사진이 필수 외부 입력이다. 사용자에게 공급자를 질문했다. 공급자 선택 전 임의 수집·로드뷰 텍스처 추출·유료 계정 생성은 하지 않는다. 독립적인 배치/주소·좌표/자료 연결 구현은 계속한다.
- S11: 로컬 웹서버/운영 HTTPS 계정·개별 저장소·백업/복원·배포 가능한 프로덕션 빌드.
- S12: WebGL 실패 시 현재 현장/메시지를 보존한 2D 대안, 저품질/동작 줄이기, 모바일/대형 화면/키보드·자원 해제.

Scenario: id/title/description, site(address/latitude/longitude/front_bearing/target_mode/source), buildings[], entities[], weather, events[], duration_seconds, mode. 사건마다 id/at_seconds/catalog_id/title/message/source_label/side/patch/private_prompt. 위치 단위 m·방향 도·연기/화염0~4는 시각 연출 강도다.

Run: 시나리오 불변 스냅샷(비공개), 현재 장면, 공개된 메시지, 논리 시계/상태, last_release_elapsed, sequence/version, 이력/회의 기록. 공개 투영에는 미래 배열·진행자 질문·비공개 메모가 없다. 기존 schema2 집합 저장·감사/멱등/CAS를 재사용해 DB 구조를 임의 변경하지 않는다.
