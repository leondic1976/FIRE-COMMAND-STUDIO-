이 문서는 GitHub 저장소의 docs/DEVELOPMENT_PLAN.md로 옮겨 개발에 착수할 수 있도록 작성한 제품 요구사항(PRD) + 시스템 설계 + 수용시험 계획이다. 실제 기관별 내부 운영지침과 편성명부는 제공받지 않았으므로, 법령상 공통 기준과 기관별 커스터마이징 영역을 엄격히 구분한다.

참석자 임무 숙지가 최우선이다. 훈련담당자의 임무 설정이 부실하면 시나리오·영상이 훌륭해도 훈련 개시를 제한한다.

대형 화면을 함께 보는 토론식 훈련이 주 기능이다. 개인용 기기·게임은 보조 기능이며, 공동 판단·지휘결론을 대체하지 않는다.

‘무각본’은 참가자의 대사·결정을 미리 정하지 않는다는 뜻이다. 훈련목표, 상황 데이터, 안전한 상황 전개 규칙은 담당자가 설계하고 검수한다.

가상 재난과 실제 사고를 명확히 구분한다. 훈련 화면·메시지·영상에 ‘훈련용/가상’ 표시를 강제하고 실제 출동·실무망과 분리한다.

훈련담당자 주도, AI 보조이다. AI API 미연결 상태에서도 핵심 기능을 온전히 작동시킨다. 향후 AI 생성물의 공개·평가·후속상황 반영은 사람의 승인을 거친다.

실감도와 정확도를 분리한다. 실사처럼 보이는 3D·연기 효과가 실제 화재·붕괴의 과학적 예측을 뜻하지는 않는다.

1. 제품 정의와 범위
1.1 해결할 문제
편성 및 담당자가 교체·순환되고 대체근무가 발생하면서 누가 어떤 임무를 언제 수행하는지 숙지 수준이 달라진다.

기존 정형화된 훈련에서는 참가자가 자신의 판단 대신 이미 정해진 순서대로 답변하기 쉽다.

재난 현장의 정보는 한꺼번에 들어오지 않는다. 영상·건물·주변 자원·안전사고·기관 요청·외부 방문객·돌발 정보가 시간차를 두고 나타나며 보고·조정·의사결정의 병목이 생긴다.

훈련 종료 후 누가 무슨 정보를 받았고, 언제 누구에게 전달했으며, 무엇을 결정했는지 기록이 분리되어 재훈련에 활용하기 어렵다.

1.2 지향점
훈련담당자가 대상물·조직·인원·임무·사건·자료·메시지·상황변화를 직접 조합하고, 소방관들이 같은 대형 상황판을 보며 각자의 임무에 따라 발언·보고·협의·결정하는 범용 재난지휘훈련 스튜디오.

1.3 초기 제품에 넣지 않을 것
실제 119 신고 접수·긴급출동·현장 지휘명령 전송 또는 실무 무전망 연동.

검증되지 않은 물리 기반 화재 확산 예측값을 사실처럼 출력하는 기능.

지도·로드뷰의 무단 저장·복제·이미지 추출·3D 텍스처 재가공.

AI가 재난 대응의 정답·법적 책임·참석자의 인사평정을 자동 확정하는 기능.

모든 대상물의 실내구조와 정밀 3D를 공공 API만으로 자동 복원한다는 약속.

2. 법령과 훈련모델 검증
2.1 대한민국 현행 현장지휘 관련 근거 [확인]
「긴급구조대응활동 및 현장지휘에 관한 규칙」 제16조는 소방본부·소방서의 긴급구조현장지휘대 상시 구성·운영 및 기능을 규정한다. 2025년 개정으로 명칭이 ‘긴급구조현장지휘대’로 정비되었으며, 2026-07-01 시행 법령을 기준으로 검토했다. [S01]

같은 규칙 별표 5는 지휘대장과 현장지휘·자원지원·통신지원·안전관리·상황조사·구급지휘 요원의 주요 임무를 제시한다. 이는 역할 유형의 기준이며 실제 훈련 참가인원 수를 7명으로 제한한다는 뜻은 아니다. [S02]

「재난 및 안전관리 기본법 시행령」 제65조는 긴급구조현장지휘대 구성·구분을 규정한다. [S03]

현장지휘규칙 제16조제3항은 통제단 설치·운영 시 요원의 통제단 해당 부서 배치 관계를 규정한다. 따라서 ‘현장지휘대 단계 → 통제단 가동 단계’ 전환 훈련을 필수 기능으로 둔다. [S01]

「긴급구조대응활동 및 현장지휘에 관한 규칙」 별표 1은 표준지휘조직에 대응계획부·현장지휘부·자원지원부 등 부서와 임무를 제시한다. 기관별 실제 운영 편성·명칭은 별도 확인해야 한다. [S04]

2.3 외국 공식 훈련방법론을 응용한 운영구조 [확인 + 설계]
미국 FEMA의 HSEEP는 토론형(Tabletop) 훈련의 상황자료(SitMan)·참가자용 자료·진행자 안내·평가표(EEG)·참가자 피드백과, 훈련 후 **AAR/IP(사후평가 및 개선계획)**를 제시한다. 본 제품은 이를 국내 법령·기관 SOP에 맞게 참고·재설계한다. HSEEP가 한국 소방에 직접 강제 적용되는 기준이라고 주장하지 않는다. [S05][S06]

역할카드 = 참가자용 간편자료(Player Handout) 응용.

상황판·진행자 질문 = SitMan/Facilitator Guide 응용.

사건 주입표 = MSEL 방식의 ‘메시지·상황변화 타임라인’을 토론형 훈련에 맞게 변형한 제품 고유 설계. HSEEP의 운영형 훈련 문서인 MSEL이 모든 토론형 훈련에 필수라고 해석하지 않는다.

평가관의 관찰증거·개선과제 = EEG, AAR/IP 개념 응용.

3. 가장 중요한 기능: 훈련담당자 초기 설정 마법사

‘3분 기본 설정’ 템플릿, ‘고급 설정’ 세부 입력, 단계별 도움말과 임무 예시.

기관별 편성표/인원표 CSV·XLSX 가져오기, 화면 편집, 오류 리포트, 재사용 가능한 템플릿 저장.

법령 기본 임무(읽기전용 원본) + 기관별 임무 확장본(버전 관리) 구조. 원본을 조용히 덮어쓰지 않음.

인원 미확정 시 ‘미배정’, 결원·대체 부재는 적색 경고로 분리 표시.

지난 훈련 복제 시 옛 담당자·옛 날짜·옛 API 자료·옛 메시지 수신자 자동 초기화 후 재검증.

훈련 상태가 ‘실행 중’이면 설정 원본을 수정하지 않고 배포된 스냅샷의 변경 이력으로 반영.

부분임무 훈련 예외: 참가자가 1~3명이면 ‘전체 조직훈련’으로 과대 표시하지 않고, ‘부분/개인 임무 숙달’ 모드로 실행한다. 미배정 역할은 명시적으로 모의요원(사전 설정 응답)으로 표시한다.

4. 인원·역할·순환·대체근무 관리
4.1 핵심 데이터 구분
RoleTemplate(직위/역할 정의): 법령·기관 규정 근거, 임무, 권한, 보고체계, 평가기준.

Person(사람): 개인 식별자는 내부 고유번호 사용; 화면에는 소속·표시명만 선택 노출.

Assignment(배치): 누가 어느 역할을 어떤 기간·근무조에 담당하는지.

BackupChain(대체순위): 1·2차 대체자, 호출/승인 권한, 대체 불가 기간.

ExerciseRoster(훈련 시점 스냅샷): 현재 편성이 바뀌어도 당시의 역할·담당자·임무가 재현됨.

Handover(인계): 현재 상황, 확인·미확인 정보, 수행·미완료 임무, 인계자·인수자, 시각.

4.2 실제 운영 규칙
사람과 역할은 다대다지만, 동일 시각에 두 핵심 역할을 맡으면 ‘겸임 여부·충돌·보고 누락 위험’을 경고한다.

배치에는 effective_from, effective_to, shift_id, assignment_status를 두고, 현재/예정/종료를 구분한다.

휴가·출장·결원·순환 시 **‘대체 발동 → 수락 → 임무카드 확인 → 인계 → 역할 활성화’**의 상태기계를 실행한다.

대체 지정만으로 숙련이 확인됐다고 보지 않는다. 대체자도 독립적으로 사전 숙지·퀴즈·인계 확인을 거친다.

훈련 도중 대체하면 교체 전후 담당자의 조치·메시지·시간을 별도 귀속시킨다. 이미 나온 지시가 사라지지 않는다.

대체자가 없거나 인계에 실패한 경우, 진행자에게 미담당 상황 주입을 제공해 지휘대장이 공백을 어떻게 해소하는지 훈련할 수 있다(사전에 의도적으로 설계한 경우에 한함).

4.3 ‘나의 임무’ 카드 — 반드시 구현
개인별 카드에는 다음이 한 화면에 나와야 한다.

현재 직위 / 보고 상급자 / 협조·보고 받을 역할 / 대체 관계

내 임무 3~7개 핵심 요약과 근거(법령·기관 문서의 버전).

첫 1분 확인사항, 상황별 우선 검토사항, 회의에서 반드시 제시할 산출물.

내가 받을 가능성이 높은 메시지 종류, 전달 대상, 보고 템플릿, 확인/회신 방식.

하지 말아야 할 권한 밖의 결정, 안전 관련 상향 보고 기준.

역할 인계 시 미완료 목록, 진행 중인 요청, 마지막 공유 상황.

실제훈련에서는 개인기기에서 카드에 접근하되, 종이/PDF 인쇄도 가능하게 한다.

카드 생성 방식: 법령 기반 원본 + 기관 승인 임무 + 해당 시나리오 목표에서 기계적으로 합성한다. AI가 만들어낸 법령이나 임무가 자동 승인 상태로 들어가지 않는다.

4.4 숙지 확인은 ‘읽음’만으로 끝내지 않는다
단계	방법	저장 근거
① 인지	역할 카드 열람, 핵심 임무 확인	읽음 시각/버전
② 이해	상황형 문항 3~5개(정보의 우선 확인·보고처·권한 구분)	답안/오답/근거/재응시
③ 설명	30~60초 구두 설명 또는 요약 기입: ‘내가 받을 정보·수행할 일·보고할 곳’	진행자 확인/간략 메모
④ 적용	실제 공동훈련에서 임무에 맞게 보고·요청·지휘판단에 참여	관찰 증거
⑤ 재학습	미숙달 임무만 다시 연습·다른 상황에 적용	다음 훈련 배정/비교
[목표/제안값] 최초 사전문항 통과 기준은 예를 들어 80%로 설정할 수 있으나 기관이 변경한다. 이 수치 자체는 법정 기준이 아니다. 점수보다 핵심 임무·보고경로를 본인이 설명하고 실제로 수행하는지를 중요하게 평가한다.

5. 훈련 진행 방식: 공동 토론 중심, 개인 연습 보조
5.1 그룹 훈련 1회 표준 흐름 [설계]
사전(훈련 전): 참석 예정·임무카드 배부, 이해도 점검, 대체/겸임 확정.

시작: 진행자가 대형 화면에 3D 대상물·인접 건물·주변 지도·초기 출동정보를 공개. ‘훈련’ 워터마크 유지.

문제 제시: 119상황실/현장/유관기관/모의 외부손님의 메시지가 도착한다. 일부는 특정 역할에게만 공개.

임무별 발언: 상황조사→안전→자원→통신→구급 등 관련 역할이 상황에 맞춰 검증 정보와 제안을 공유한다. 고정된 답변 순서는 강제하지 않는다.

지휘결론: 지휘대장이 우선순위, 지시 내용, 자원배치, 미확인 위험, 재보고 시점을 정리한다.

상황 변경: 진행자가 판단에 부합하는 후속상황을 승인해 공개. 건물 3D 상태·지도·차량·연기·출입구·인원 정보가 함께 바뀐다.

반복: 위험 징후, 통신 두절, 지원기관 방문, 인명구조 필요, 부상·대원 안전사고 등 새로운 변수를 주입한다.

종료/강평: 타임라인을 재생해 역할별 조치·협조·누락·판단 근거를 확인하고 AAR/개선과제를 확정한다.

권장 운영 예시(제안값): 사전점검 10분, 상황/토론 35분, 지휘판단 정리 10분, 강평 15분 등. 각 기관은 시간·상황 개수·토론 강도를 자유롭게 변경한다.

5.2 개인 연습(Solo)
참가자가 한 역할을 선택하고, 다른 역할의 보고는 사전에 작성한 모의 응답/훈련 엔진이 제공한다(AI 없이도 동작).

3D 화면과 메시지에 따라 본인의 조치·보고·인계 판단을 퀴즈/단문/선택형으로 연습한다.

난이도는 초급(도움말 있음) → 실무(정보 일부 누락) → 고급(복수 돌발·시간 압박)으로 설정한다.

평가 결과를 그 역할의 다음 공동 훈련 사전 학습에 연결한다. 단, 개인 게임 점수를 곧바로 실전 지휘역량의 절대 평가로 사용하지 않는다.

5.3 메시지·보고의 폐루프(closed-loop) 기록
메시지마다 아래 흐름을 지원한다.

발신 → 수신 → 확인(사실/추정/오보) → 담당자 인지 → 보고/협조 전파 → 결정/조치 → 회신 → 종결

음성으로 말한 조치도 진행자/평가관이 버튼으로 기록할 수 있어 모든 참석자에게 스마트폰 조작을 강제하지 않는다.

개인 메시지는 본인/허가된 수신자만 조회한다. 대형 화면에는 공개 승인을 얻은 메시지와 공통 상황만 표시한다.

정보가 늦게 오거나 모순되면 확인·재요청 자체가 평가 대상이 되며, 임의로 ‘정답’을 화면에 먼저 공개하지 않는다.

6. ‘만능’ 상황훈련을 위한 범용 시나리오 엔진
6.1 원칙: 재난별 프로그램을 만들지 않고 사건 조립기로 만든다
하나의 고정된 공장화재 프로그램이 아니라 대상물 + 현장상태 + 등장주체 + 자원 + 시간 + 메시지 + 행동/판단 + 상황변화를 조합하는 공통 엔진을 개발한다.

구성요소	훈련담당자 설정	재사용·확장 방식
재난 분류	화재·폭발·붕괴·침수·지하공간·다수사상자·위험물·산불·수난·복합재난	자유 태그 + 표준 템플릿(특정 재난 유형으로 제한하지 않음)
대상 공간	실제/가상 건물, 인접건물, 도로·지하·주변 지도	장면 플러그인(BUILDING_3D / MAP / UNDERGROUND / ROAD / MARITIME 등)

참여·외부주체	119상황실, 현장대원, 구급대, 경찰·지자체, 주민, 언론, 방문객	발신자 역할을 자유롭게 생성

재난정보	연소·연기·유해물질·붕괴징후·피난·사상자·장애물·날씨	사실/불확실/오보 구분

6.2 시나리오 제작 화면의 세 부분
콘텐츠 라이브러리: 사고·대상물·영상·음성·메시지·임무 카드·평가 문항 템플릿.

상황 타임라인: ‘사건 카드’를 배치하고 시각·수신 역할·공개 범위·연결 장면·필수 응답 지정.

분기 편집기: 참가자의 선택 또는 진행자가 기록한 판단/성과에 따라 다음 사건과 공간상태를 전환.

‘사건 카드’ 하나에 반드시 포함할 필드:

ID, 제목, 사건 범주, 훈련목표 연결, 모의 발생시각.

발신 주체, 수신 역할/그룹, 보안공개 범위, 우선순위, 전달 채널(무전/전화/메신저/현장관찰/영상).

메시지 원문(정보 일부가 틀리거나 늦을 수 있음), 첨부자료, 3D 공간 앵커, 위치/좌표.

발생 조건(시간·수동승인·앞 사건 완료·특정 결정·자원 상태), 재주입/취소 가능 여부.

예상 행동 후보와 관련 임무·평가 기준. 이 항목은 진행자만 조회하며 참가자에게 정답으로 공개하지 않는다.

상황 변화(건물 상태·인원·차량·출입구·소화전·지도·영상), 후속 분기, 안전상 중단 조건.

연출/실제 출처 구분, 작성자·검수자·버전.

6.3 이벤트 분기 처리의 안전한 규칙
MANUAL: 진행자 승인 시 발화.

AT_TIME: 훈련시계가 지정 시각에 도달하면 후보 표시. 자동공개는 사전 허용된 항목만.

ON_ACTION: ‘자원요청 승인’, ‘재확인 보고 완료’ 등 구조화된 참가자 조치 발생.

ON_CONDITION: 자원 부족, 특정 출입구 폐쇄, 통신 장애 등 지정 상태 조건 충족.

ON_COMBINATION: 여러 조건의 AND/OR 조합. 표현식은 제한된 DSL로 해석하고 임의 JavaScript/Python 코드 실행을 금지.

분기 불변식: 사건 ID와 상태 변경은 중복 적용되지 않아야 한다(멱등성). 참조하지 않는 사건·순환분기·도달 불가능한 종료·충돌하는 공간 상태는 게시 전에 검사한다. 훈련 중 되돌리기는 과거 이벤트를 삭제하지 않고 **‘되돌림 이벤트’**로 기록하여 재생 가능한 타임라인을 유지한다.

6.5 작성자 자유도를 지키면서 품질을 확보
사건 종류와 메시지·첨부의 개수는 임의로 추가할 수 있다. 정해진 시나리오 제목이나 카드 수로 사용을 제한하지 않는다.

저장 시 필수 목적·수신자·발생조건·현장상태 관계만 스키마 검사하고, 인위적인 ‘정답 메시지 문구’를 강요하지 않는다.

불확실한 정보는 truth_status=UNCONFIRMED로 표시할 수 있으나 평가관의 정답표는 비공개.

기본 제공 템플릿은 적어도 ‘공장 화재/고층건물/지하공간/복합재난’ 등 다양한 위험 구조를 보여주는 가상 예제로 시작하되, 특정 템플릿에 의존하지 않도록 한다.

7. 실제 대상물·가상 대상물·인접건물·주변지도
7.1 대상물 구분은 선택 옵션이 아니라 핵심 필드
대상물 유형	데이터 입력 경로	화면에 반드시 표시할 내용
REAL(실제 소방대상물)	실주소/좌표, 승인된 공공 API, 실제 건물모델·현장조사·권한 있는 사진·도면	‘실제 대상물 기반 가상 상황훈련’, 데이터 기준일, 출처, 모델 정확도
VIRTUAL(가상 대상물)	훈련담당자가 생성한 가상 주소·3D 건물·주변 환경·자원·도면	‘가상 대상물/가상 배치’, 현실의 특정 시설과 무관함
VIRTUAL_ON_REAL_MAP(선택적 혼합 모드)	실지도 위에 임의의 가상 건물을 놓는 연출	‘실지도 + 가상 건물’ 상시 표시. 실제 존재하는 시설로 오인하지 않게 경계선·범례 구별
두 축을 분리한다. 실제 대상물을 사용하더라도 재난 시나리오의 사건·화재·피해·부상자는 가상일 수 있다. 따라서 target_mode와 scenario_factuality를 별도로 저장한다. 예: 실제 물류창고 + 가상 화재. 실제 사고의 기록·재연은 별도의 출처·승인·익명화 절차를 거친다.

7.2 주변 환경은 주건물만큼 중요
각 대상물에서 기본 표시:

주대상물: 3D 외관, 층수/용도/구조, 출입구, 계단, 소방시설·위험구역(정보가 있을 때), 화점/연기/고립 지점.

인접 건물: 인접 동·호/동번호·용도·이격·높이·외장재 등 확인 가능한 항목만 표시, 3D 볼륨과 외관. 연소확대 위험에 대한 토론용 영역을 표시하되 실제 위험도 계산과 구별.

주변 지도: 도로 폭·진입방향·교차로·교통통제·소방용수·자원집결지·119안전센터·병원·대피 공간.

현장 시야: 드론영상, 차량전방영상, 허가된 거리뷰, 촬영 사진, 건물 평면도·단면도·층별 표시.

상황 변화: 인접동 노출·차량 접근로 폐쇄·소방용수 장애·대피지역 확장·안전구역 지정이 타임라인/지휘결정과 연동.

중요: 인접 건물의 외관·사용현황·실내 구조는 자동으로 정확하다고 가정하지 않는다. 없는 정보는 ‘미확인’으로 표시하며 훈련담당자가 보완하거나 가상 데이터로 생성한다.

7.3 카카오맵·로드뷰 연동: 허용된 화면 표시와 별도 사진 이용권의 구분
카카오 공식 지도 Web API는 지도 표시, 마커·오버레이, 로드뷰 객체, 위치 기반 가까운 파노라마 조회 및 지도-로드뷰 연동을 지원한다. [S10][S11]

1차 구현(권장, 공식 SDK 범위):

주소 또는 좌표 입력 → 승인된 지오코딩으로 위치 확정.

대형 상황판의 ‘주변 지도’ 영역에 카카오 지도 SDK 표시. 대상물·인접건물·차량·소화전·통제선을 별도 오버레이로 표시.

‘거리뷰’ 버튼 → 로드뷰 공식 API 위젯을 열고 주변 도로의 실제 촬영 시점 참고. 로드뷰가 제공되지 않는 지점은 이용 불가 안내.

3D 건물과 지도·로드뷰의 선택 위치를 동기화(선택한 건물·도로·방위각·좌표). 지도 로고·출처와 서비스 약관 준수.

2차 구현(별도 권리 검토 후):

카카오맵·로드뷰의 화면을 수집·캡처해 재가공하거나 3D 외벽 텍스처로 저장·재배포하는 기능은 기본 비활성.

공식 SDK에서 로드뷰를 ‘보여줄 수 있다’는 사실이 ‘로드뷰 사진을 추출해 다른 3D 엔진의 텍스처로 쓸 권리’를 곧바로 부여하는 것은 아니다. 별도 허가·적용약관 확인 후에만 구현.

권한을 확보하지 못하면 기관이 직접 촬영해 적법하게 보유한 사진, 허가받은 자료, 상용 허가 텍스처, AI가 생성한 가상 재질을 이용한다.

외부 지도 이용 가능 여부는 네트워크, API 키 등록 도메인, 호출량·요금정책·이용조건에 영향을 받는다. 운영 배포 직전에 재검토한다. [S10][S11]

7.5 ‘가상 대상물 생성기’ — GUI에서 자유롭게 제작
훈련담당자는 실제 소재지 없이도 다음을 만들어야 한다.

용도 프리셋: 공장·창고·지하상가·고층아파트·다중이용시설·의료시설·학교·위험물 시설·지하차도·복합건물.

외관 제작: 지면을 클릭해 건물 윤곽 다각형 작성 → 층수·층고·높이·지붕·외벽 재질·창호/출입구·연결통로 설정.

내부 제작: 층별 윤곽, 실·복도·계단·승강기·방화구획·피난통로, 소방시설·위험물 저장구역 선택적으로 추가.

인접건물 생성: 주건물에서 거리·방위·높이·용도·배치 입력, 복사/회전/크기 변경, 도로·주차장·소방용수·집결지 편집.

실사형 텍스처: 허가된 PBR 재질 라이브러리, 사진 업로드, 향후 승인된 생성형 이미지로 외관 재질 제작(가상 자료임을 표시).

사건 앵커: 3층 창문, 북측 출입구, 지하 2층 계단, 인접동 외벽 등 3D 요소에 메시지·위험·영상을 연결.

자동 검증: 건물-층-구역 참조 누락, 출입구 미설정, 중복 층번호, 비현실적 치수 경고. 위험 시나리오의 사실성 최종 판단은 훈련담당자.

배포: GLB/glTF + 장면 JSON + 출처/저작권 메타데이터로 버전 고정. 이후 다양한 훈련에서 복제·편집.

7.6 주변지도와 3D의 위치 동기화
지도 위치의 기준 좌표는 WGS84 위·경도로 저장하고, 3D 렌더러는 대상물 중심의 지역 로컬좌표계로 투영한다. 거리·높이 단위는 m로 통일.

모델 원점·북쪽 방향·회전각·바닥 기준고·중심좌표를 필수 메타데이터로 둔다.

대상물/인접건물/소화전/차량 아이콘을 지도와 3D에서 동일한 ID로 참조한다.

좌표 오차 허용치(설계): 모델 소스에 맞는 정확도 등급을 붙이고, 훈련담당자의 지도-3D 수동 보정/확인 절차를 제공한다. 미확인 위치를 ‘정확’으로 표기하지 않는다.

8.4 변화 구현 시 지켜야 할 7가지
사실(데이터)과 효과(시각화)를 분리한다. 3D 화염은 훈련담당자가 지정한 구역을 강조하는 연출이며, 과학적으로 계산한 화염 길이·연소속도라고 주장하지 않는다.

객체 식별자 기반으로 변경한다. ‘화점 3층 북측’은 3D·지도·영상·메시지에서 같은 객체/구역 ID를 참조한다.

변경은 상태 패치(전/후 값) 형태로 저장한다. 진행자가 ‘연기 확대’ 버튼을 누르면 변경할 구역과 수준을 미리 확인할 수 있다.

지휘결정으로 분기될 때 후속 사건과 화면 변경을 묶어 원자적으로 적용한다. 중간에 영상만 새로 보이고 3D가 구버전인 상태를 방지한다.

모든 시각변화에는 상황 라벨과 시각을 표시한다. 예: ‘훈련용 · 14:12 · 3층 북측 연기 확산(연출)’.

현장 3D·지도는 회전·확대·위치 이동·건물 분리보기·층 숨기기·단면/층별 보기·원위치를 지원한다.

3D 작동이 어려운 PC에서는 해당 장면의 사전 렌더링 이미지/동영상 또는 2D 평면도로 자동 전환하되, 같은 사건·상황정보를 유지한다.

선택적 고급 연동: NIST FDS/Smokeview 결과를 사전 계산된 시뮬레이션 데이터로 불러와 시간별 열/연기 레이어를 재생할 수 있다. 다만 NIST는 별도의 검증/타당성 문서를 제공하므로, 실제 시설의 정량적 화재예측이라고 표시하려면 입력조건·모델 검증이 필요하다. [S15]

8.5 프레임·속도·사용성 목표 [목표]
기준환경: 기관 시연 PC의 CPU·GPU·RAM·브라우저·모니터 해상도를 먼저 고정하고 기록한다.

초기 목표: 1080p 기준의 통상 규모 가상 건물+인접동 장면에서 24fps 이상, 장면 조작 중 메시지·지도 사용 가능; 성능이 낮으면 재질 해상도·입자 수·그림자 품질을 자동 감소.

초기 로딩 목표: 데모 3D 자산은 10초 이내 첫 화면(정확한 기기·네트워크 조건과 측정 결과 함께 보고).

공동 화면 동기화 목표: 진행자의 사건 공개 후 공용화면/평가관 화면에 2초 내 반영(기관 LAN 테스트 기준).

측정: 3D 장면 삼각형 수·텍스처 용량·FPS·메모리·네트워크 전송량 로그를 남기고, 24fps 미달 시 기능 실패가 아니라 품질 저하 및 2D 전환 기록.

이 숫자는 프로젝트 자체 수용 기준의 초안이며, 기존 시스템 실측치나 법정 기준이 아니다.

8.6 실제 사진 기반의 실사형 외관 제작 파이프라인 [설계]
원본 확보: 기관이 직접 촬영한 사진, 소유권·이용허락이 확인된 항공/지상 사진, 사용 허가된 3D/BIM 자산을 우선 사용한다. 촬영이 불가한 대상물은 모사 건물 프리셋으로 대체한다.

출처·권한 등록: 촬영자·촬영일·대상 위치·이용범위·내부 공개 가능 여부·원본 파일 해시를 자산마다 기록한다. 로드뷰는 별도 허가가 없는 한 SDK 화면 안에서만 참조한다.

형상 구성: 실측/승인된 도면 기반 건물 치수를 설정하고, 사진 보정·파사드 분할·창호/외장재 모델링 또는 허가된 사진측량으로 3D 형상을 만든다. 단일 거리 사진만으로 뒤편·내부 구조를 정확히 복원했다고 주장하지 않는다.

재질 제작: 사용 권한이 있는 사진을 PBR 재질의 색상·거칠기·법선 맵 등으로 가공하고, 원본에 없는 부분은 가상 보완으로 표기한다. 현장과 다른 창문·피난계단·출입구를 임의 생성하면 정확도 검토를 거친다.

인접동 적용: 주건물과 같은 라이선스·정확도 체계를 적용하되, 사진이 없는 인접동은 L0/L1 근사 모델을 혼합한다. 지도에 나타난 건물이 실제로 존재한다는 사실과 3D 외관이 정확하다는 주장은 별개다.

최종 검수: 방향·층수·이격·진입로·외부 소방시설 위치를 담당자가 대조하고, 사용자 화면에는 실제 촬영 외관 / 실측 기반 모델 / 가상 모사 등 출처 등급을 보여준다.

실사 품질의 원칙: 색감·광원·그림자·재질을 고급화하되, 실제 구조와 다른 내용을 사실처럼 보이게 하는 ‘거짓 정밀도’를 금지한다.

9.4 화면 전환의 안전성
실제 대상물 모드와 가상 대상물 모드는 항상 눈에 보이는 배지 색상+문구로 구별한다.

실지도 위의 가상 건물은 가상 윤곽을 점선으로 표시하고 툴팁에 ‘존재하지 않는 훈련용 건물’ 경고.

3D와 지도/로드뷰의 시간이 서로 다를 수 있으므로 촬영 시각·자료 기준일·훈련시각을 별개로 표시한다.

인터넷 중단 또는 외부지도 SDK 장애 시 사전 승인된 로컬 지도·도식·가상건물로 계속 훈련한다. 카카오 지도 데이터를 이용약관에 반해 임의로 캐시하지 않는다.

9.5 고품격 상황판 시각 규격 [설계]
일관된 디자인 시스템: 절제된 짙은 남색·중성 회색을 기본으로 화재·위험·경고·확인 상태만 의미 있는 강조색을 사용한다. 소방 무전·안전현장 도식에서 익숙한 용어와 범례를 사용하되, 기관 표준 디자인 지침이 있으면 우선한다.

고급 3D 품질: 허가받은 PBR 재질·환경광·상황별 그림자·현실적인 스케일·부드러운 카메라 전환을 사용한다. 불필요한 폭발/연기 특수효과·게임 점수 연출은 회의식 판단을 방해하지 않도록 절제한다.

회의실 가독성: 16:9 대형 모니터 기준, 뒷좌석 참가자의 글씨 식별·색각 차이·자막·지명 식별을 실사용 테스트한다. 3D 화려함 때문에 역할과 메시지가 가려지지 않게 한다.

한눈에 판단: 사건마다 새 정보 → 출처/확실성 → 영향 대상 → 보고해야 할 담당자 → 미결정 사항을 동일 패턴으로 표시한다.

운영자와 참가자 화면 구별: 진행자 비공개 예고·분기·정답은 공용 화면에 잠깐도 노출하지 않는다. 화면 공유/미러링 설정도 사전 테스트한다.

사진·영상 품질: 로드뷰/실제 촬영 영상/가상 생성 이미지는 각각 육안으로 구별 가능한 레이블을 붙이고, 확대해도 근거 없는 세부정보가 ‘사실’로 보이지 않게 한다.

10.2 데이터 유입 과정
공급자 선택: 수동 / CSV·XLSX / JSON·GeoJSON / IFC·GLB / 승인된 외부 API.

파일·응답 검사: 포맷, 크기, 악성 파일, 인증키 비노출, 예상 좌표계, 필요한 필드, 이상값.

정규화: 주소/좌표/건물 ID, 층·구역, 차량/소화전 유형, 단위와 시각을 통일.

출처 레코드 저장: 제공처, URL 또는 문서명, 조회 시각, 원자료 시점, 권리·공개제한, 원본 해시.

사용자 확인: ‘불러온 값’과 ‘직접 수정한 값’을 나란히 표시하고 확정.

상황 스냅샷: 훈련 게시 시 외부 자료를 훈련용 스냅샷으로 고정(원천 약관상 저장 허용되는 범위). 허용되지 않는 지도/로드뷰 데이터는 캐시하지 않고 참조 정보만 보관.

정기 점검: 건물·소방용수 데이터의 정확도 검증 및 정정 기록.

실패 처리 예: 건축물대장 API로 건물 ‘용도’를 불러왔어도, 3D 실내 피난계단이 없으면 ‘미확인/도면 필요’로 표시한다. 자동으로 임의의 계단을 생성해 실제 구조인 양 표시하지 않는다. 가상 대상물에서는 임의 생성이 가능하다.

세션 종료 후 수정은 원본 상태를 조용히 변경하지 않고 ‘사후 보정’으로 별도 기록.

12. AI API 확장을 고려한 독립 설계
12.1 AI가 없어도 v1이 동작해야 하는 이유
‘무각본’의 핵심은 사용자 행동·토론이 미리 정해지지 않는 것이지, AI에 맡겨 통제가 불가능한 사건이 무한히 발생하는 것이 아니다. v1에서는 담당자가 검토한 사건과 결정론적 조건분기로 현실감·재현성·평가 신뢰도를 먼저 확보한다.

단독 연습과 10인 그룹 훈련의 점수는 동일 척도로 단순 서열화하지 않는다.

15.3 테스트 자동화와 실증
유닛: 사건 조건식·상태 패치·권한·근무조/대체 충돌·평가 산식·자료 출처 검증.

통합: 편성스냅샷-메시지-3D-지도-평가 AAR 간 동일 ID·시퀀스 확인.

E2E: 진행자 작성 → 담당자 숙지 → 10명 역할 배치 → 모의 상황 6개 이상 → AAR 생성.

속성기반/퍼즈 테스트: 사건 순서 중복·불완전 JSON·음수 층수·다중대체 순환·비정상 좌표·잘못된 GLB.

데이터 공급 실패: 카카오 API 키 없음·기상 API timeout·건축물 API 필드 변경·로드뷰 없음.

보안: 기관 간 자료 접근, 미발행 시나리오 누출, 외부 사진 재가공 경로, 실제 지휘망 접근 차단.

사용자 검증: 현장지휘대/통제단 임무 경험자가 초기 설정·역할카드·상황분기·강평을 직접 수행. 관찰기록에 개선점을 남겨 재시험.

전문가 정합성: 법령·기관 SOP 버전 및 심사자 승인 기록을 남기고 시범 운영 전 갱신 확인.

출시 보류 기준: AC-01/04/06/07/09/13/19/23/25/29/32/35 중 하나라도 실패하면 기관 정규 훈련용 출시 보류. 화려한 그래픽으로 이를 상쇄하지 않는다.

17.1 반드시 먼저 완성할 최소 핵심(MVP)
법령 기반 역할+기관별 임무 설정 및 인원·대체근무 관리.

참가자 개인 임무카드·사전숙지 테스트.

훈련담당자 사건/메시지/조건분기 편집기와 품질 검사.

대형 화면 공동 토론 진행, 기록·결정·메시지 폐루프.

가상 3D 주건물+2동 이상 인접건물 + 주변 로컬지도, 사건에 따른 연기·출입구·차량·위험구역 변화.

실제/가상 대상물 모드 구분과 출처·훈련 워터마크.

평가/AAR·재생·백업.

MVP 이후 확장: 실제 대상물 상세모델/사진, 인터넷 Kakao 지도·로드뷰, 고급 3D 타일, BIM 내부공간, AI API. 단, 사용자가 원한 기능 자체는 MVP 설계·인터페이스에 포함하고 기능별 제공 상태를 표시한다.

17.2 시범훈련 운영 검증
진행자 1명, 참가자 약 10명, 평가관 1명으로 실제 회의실·프로젝터·사용 PC에서 테스트한다.

18.2 개발 규칙(AGENTS.md에 포함할 사항)
개발자가 새 기능을 추가할 때 어느 사용자 요구/AC를 충족하는지 PR에 적는다.

법령·기관 편성의 의미를 AI가 임의로 바꾸거나 승인문서를 만들어내지 않는다.

실제 대상물/가상 대상물/가상 사고는 타입이 다른 데이터이며, 화면에 올 때 출처 표시를 제거하지 않는다.

화면 효과의 연기·화염 상태는 훈련용 시각효과로 유지하며, 실제 공학 데이터라는 문구를 금지.

외부 API·로드뷰 텍스처 사용은 권리 검토 없이는 차단하고, 테스트는 합성 사진·허가된 자산 사용.

기능 테스트 외에 기관 간 접근제어·공용화면 비공개정보 유출 테스트를 통과해야 병합.

코드를 먼저 쓰기보다 데이터 스키마와 예제 시나리오가 검증 가능한 형태인지 확인.

DB 변경은 마이그레이션·롤백/백업 방안을 포함하고, 실행 중 세션의 기록 재현성을 깨지 않음.

외부 API 키/비공개 명부/현장도면을 Git 커밋·테스트 스냅샷·디버그 로그에 넣지 않음.

사용성 변경은 진행자·참가자·평가관의 실제 훈련 흐름을 기준으로 검증.

22. 최종 개발 승인 기준
본 제품의 경쟁력은 화려한 이미지 하나가 아니라 다음 조건이 연결되어 실제로 작동하는 것에 있다.

훈련담당자가 정확한 임무와 담당자·대체자를 스스로 설정하고 검증할 수 있다.

참석자는 누구나 자신의 역할·보고경로·핵심 임무를 알고 훈련을 시작한다.

실제/가상 대상물 모두 주건물과 인접건물의 현실감 있는 3D 화면·주변 지도를 제공한다. 실제 사진/로드뷰는 사용 권한에 따라 표현한다.

119상황실·현장·차량·소방용수·안전사고·방문객·유관기관 등 범용 메시지가 임무별로 전달되고, 참가자의 보고·토론·지휘판단에 따라 건물 3D와 상황이 변화한다.

모든 결정과 인계·상황변경이 재생 가능하고 역할별 관찰증거·AAR·재훈련으로 이어진다.

AI API가 없어도 위 기능을 수행하고, 향후 AI는 자료 보호와 사람의 최종 승인 아래 보조한다.

출시 판단: ‘임무 숙지 + 공동 토론 + 상황변화 + 평가/개선’의 한 사이클을 실제 참석자 약 10명이 무리 없이 수행하고, 객관적인 테스트·보안·기관 검수에 통과한 때에만 정규 훈련용으로 배포한다.
