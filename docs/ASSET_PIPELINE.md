# 허가 모델·사진과 오프라인 IFC

2026-11-17 기준 **구현된 계약과 운영 절차**다. plan §7.5/8.2/8.6/14.2와 AC-13/17/18/30/31에 연결한다. 아래 계약을 구현하고 합성 자료로 시험했다. 실제 기관 자산 이용권·형상·악성코드 검사기 승인을 대신하지 않는다. 정확한 실행 수치는 TEST_PLAN과 버전별 evidence에 기록한다.

## 데이터와 수명주기

- Asset: 기관 ID, 서버 생성 ID, 파일 SHA256/크기/실제 형식, 원본 출처·제작자·촬영/자료 기준일·대상물·이용범위·보안분류, 원본/정규화본 버전, 구조 검사·악성코드 검사·변환 도구 버전/결과를 보관한다. 임의 경로나 URL은 입력받지 않는다.
- 수집 상태: `QUARANTINED → VALIDATED` 또는 `REJECTED`. 사람 검토 완료는 Asset 상태를 바꾸는 대신 별도 연결/검토 이력으로 저장한다. 검사 실패·미실행·권리 미확인은 발행/공개 콘텐츠 제공을 차단하며 VALIDATED 편집자 미리보기는 사람 검토를 위한 경로다. 자동 구조 검사와 이용권/좌표 검토는 별개다.
- ModelBinding: 건물 ID, 자산 ID/고정 해시, 모델 단위(m), 위치/회전/축·범위, 층/객체 ID 매핑, 정확도/실내 검증 범위, 공개 범위, 검토자/시각/메모를 가진다. 일반 편집으로 승인 이력을 위조하지 못하게 전용 CAS/멱등 검토 경로를 사용한다.
- 발행·실행 스냅샷은 해시로 내용을 고정한다. 변경은 새 자산/바인딩 버전이다. 수집 당시 권리와 새 훈련의 재사용 가능 여부를 확인하며, 복제가 승인을 자동 승계하지 않는다.
- 콘텐츠 파일은 런타임 비공개 저장소에 보관한다. 미검토 자산에 정적 URL을 발급하지 않는다. 모든 GET/목록/미리보기에서 기관과 해당 훈련/실행본의 역할·공개 범위를 확인한다. 공용/참관 투영에서 제외한 자산은 콘텐츠 API도 거절해야 한다.

## 구현된 입력 순서와 실패 대안

1. 합성 GLB/사진과 손상·과대·외부 URI·경로 탈출·NaN·순환 노드·중복/누락 매핑 입력을 먼저 준비한다. 실제 도면/사진을 시험 증거에 넣지 않는다.
2. 업로드를 제한 크기로 격리한다. GLB는 바이너리 청크/버퍼 범위·접근자/정점·삼각형·계층·유한 좌표·재질/내장 이미지 예산을 검증한다. 지원하지 않는 확장/압축/외부 의존성은 명확하게 거절한다. 원본 이름을 경로로 사용하지 않는다.
3. 악성코드 검사 어댑터는 기관 승인 로컬 검사기를 사용한다. 미설정/타임아웃/오류를 CLEAN으로 간주하지 않는다. 합성 검사기 시험과 실제 검사기 연결 시험을 구분한다.
4. 검사·사람 검토 이후 GLTFLoader로 경량 모델을 로딩한다. 층별/객체별 조회, 로컬 위치/북향·높이·층고를 대조한다. 실패/예산 초과 시 원래의 근사 모델/2D로 전환하고 정확도 라벨을 유지한다.
5. 사진은 이용권/촬영 범위·위치를 검토하고 메타데이터 제거·크기 제한·표준 형식 재인코딩 후 재질/참고 화면에 사용한다. 색상맵의 적용이 실제 거칠기·법선·뒤편/실내를 검증했다는 뜻이 아니다. 가상 보완 부분을 표시한다.
6. IFC는 승인된 도구를 격리된 오프라인 작업으로 실행한다. 명령 셸/사용자 인수·임의 실행파일·네트워크 의존성은 허용하지 않는다. 변환본도 GLB와 동일한 검사/검토를 거친다. 도구가 없거나 변환 실패 시 입력 오류와 수동 GLB/근사 모델 대안을 제공한다.
7. 백업/복구에는 DB와 참조 콘텐츠의 해시·버전 매니페스트를 함께 포함한다. 누락/변조를 검출한다. DB 필드/스키마 변경 시 기존 JSON의 기본값과 업/다운그레이드·복구 범위를 기록한다.

## 검증 범위

정상·오류·기관/역할/콘텐츠 격리·동시 수정·멱등 재시도·재시작/백업복구·발행본 불변성·AAR 이스케이프/출처·변환 작업 제한을 시험했다. 두 브라우저에서 모델/층·객체 선택/배치·권리 게이트와 비공개 콘텐츠 차단을 확인했다. 외벽 사진·최종 인쇄·60분 시험은 실행 후 TEST_PLAN에 결과를 추가한다. 실제 승인 자산·악성코드 검사기·기관 PC·자료 대조는 제공 전까지 미검증으로 남긴다.


## 사전 기술 확인 (구현/검사 통과와 구분)

구현 전 Pillow12.2.0·IfcConvert 미설치를 확인했고, 이후 Pillow13.0.0과 고정 IfcConvert0.8.5로 검증했다. Defender 실행파일은 존재하지만 조회된 검사 서비스/AntivirusEnabled는 false였다. 파일 존재를 실제 검사기 동작이나 CLEAN 판정으로 취급하지 않으며 검사 서비스 설정을 바꾸지 않았다.

- [Three.js GLTFLoader 공식 문서](https://threejs.org/docs/pages/GLTFLoader.html): ArrayBuffer parseAsync와 모델 자원 정리 기준. 프로젝트에 설치된 Three.js0.182 코드와 대조해 구현한다.
- [IfcOpenShell IfcConvert 공식 사용법](https://docs.ifcopenshell.org/ifcconvert/usage.html): IFC→GLB CLI 계약. 실제 기관 호스트 승인/AV와 합성 입력의 실제 변환 시험을 구분한다.
- [Microsoft Defender CLI 공식 문서](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus): 실행 권한·검사 옵션·오류 구분. 관리자 권한이 필요한 실행을 애플리케이션 권한 상승으로 해결하지 않는다.

## 화면과 서버 경로

‘건물·지도·자원 → 허가 모델·사진 입력’에서 파일·제작/촬영 주체·원천·기준일·이용범위를 입력한다. 업로드 이름은 경로로 사용하지 않고 원천 주소는 HTTPS 참조만 보관한다. 파일당15MiB, GLB20만 삼각형/2천 노드, 전체 연결50만 삼각형/16M 텍스처 픽셀, 기관별500개/200MiB 제한을 적용한다. 목록은 최근100개다.

GLB는 정적 core glTF2.0의 단일 JSON/BIN만 지원한다. 실제 정점으로 경계를 다시 계산하고 extras/생성기 정보는 제거하되 정식 저작권 표시는 보존한다. 사진은 실제 PNG/JPEG, 최대4096px/16M 입력 픽셀·최대2048px 정규화 RGB PNG다. 메타데이터를 제거하고 정규화본을 다시 검사한다. VALIDATED는 사람 검토 전 상태이며, 권리/좌표 확인과 메모가 있어야 초안에 연결된다. 연결/교체/해제는 전후 매핑 이력을 보존한다.

초안·실행본·공동화면 콘텐츠 API는 기관/역할/해시를 검사한다. 공동화면 전용 경로는 진행자 쿠키라도 공개 투영을 강제하고 STAFF/INTERNAL 자산은404로 차단한다. no-store·nosniff·고정 MIME을 사용하며 정적 파일 URL은 없다. AAR JSON/Markdown/인쇄에 제작자·이용범위·기준일·층 매핑·해시를 남기고 비공개 검토 메모는 제외한다.

브라우저는 해시 확인 후 GLTFLoader로 로딩하고 외부 참조를 차단한다. 전체 행렬을 보존한 정적 메시를 층별로 분리하며2D/3D 보정 함수를 공유한다. 최대32MiB 컴포넌트 캐시와 자원 해제/취소를 적용한다. 외벽 사진은 지정한 한 면의 색상맵이며 거칠기/법선·다른 면·실내의 실측 검증이 아니다.

## 로컬 검사기 설정

기본은 비활성이다. 운영자가 승인된 같은 호스트 clamd INSTREAM을 설치·갱신·검증한 뒤 서버 환경에 `ASSET_SCAN_APPROVED=true`, `ASSET_SCAN_APPROVAL_REF`, `CLAMD_PORT`를 설정한다. 주소는127.0.0.1 고정이며 정확한 `stream: OK` 응답만 CLEAN이다. 미설정/오류/시간초과는 격리를 유지한다. 시험의 `synthetic-protocol-fixture`는 의존성 주입된 합성 응답이며 실제 AV가 아니다. 검사기 선택 질문은 답변 대기이고 운영 설정은 꺼져 있다.

## 오프라인 IFC 절차

HTTP 서버는 변환 프로세스를 실행하지 않는다. 기관이 승인한 오프라인 Windows 호스트에서 별도 CLI를 사용한다. UTF-8 STEP IFC2X3/IFC4/IFC4X3_ADD2만 지원하며 ZIP/XML·외부 URL/파일 참조는 거절한다.

```powershell
python scripts/prepare_ifc_tool.py runtime/tools/ifcconvert-0.8.5
# 기관 승인·오프라인 네트워크 차단·실제 검사기 확인 후에만 환경 설정
# IFC_CONVERSION_APPROVED, IFC_CONVERSION_APPROVAL_REF, IFC_OFFLINE_HOST_CONFIRMED
# IFC_TOOL_MANIFEST, IFC_TOOL_MANIFEST_SHA256 및 위 검사기 환경변수
python scripts/convert_ifc.py 승인된입력.ifc 새출력.glb
```

설치기는 [공식0.8.5 배포](https://github.com/IfcOpenShell/IfcOpenShell/releases/tag/ifcconvert-0.8.5)의 고정 win64 ZIP만 내려받고 SHA256 `36e9a527f57c0894138cf7df29d299c378d90bcbf468abf93a59e32c9d89cd48`을 확인한다. 도구 활성화/기관 승인 없이 실행파일/DLL 전체 해시 매니페스트를 생성한다. 재현 매니페스트 SHA256은 `112a4d32189d06c7e3595587d8c88b0c7c86e6833d61519fe4133b72089daa40`이다. 변환 시 전체 해시·추가 DLL/심볼릭 링크를 검사한다.

프로세스는 셸 없이 중단 상태로 생성해 Windows Job에 배치한 후 재개한다. 메모리1GiB·프로세스1개·CPU/벽시계 시간·출력 크기를 제한한다. 입력을 쓰기 전에 현재 사용자 전용 보호 DACL을 설정한 임시 디렉터리를 사용하고 비밀 환경변수를 전달하지 않는다. **Job 자체는 네트워크를 차단하지 않는다.** 별도 오프라인 호스트/방화벽 차단은 운영자가 확인해야 하며 플래그만으로 검증 완료라고 기록하지 않는다.

원IFC→변환GLB→정규화GLB 각각 검사 후 새 GLB와 `.glb.conversion.json`을 생성한다. 기존 출력은 덮어쓰지 않는다. UI는 선택한 변환 기록의 출력 해시를 업로드 GLB와 대조한다. 제공자 선언이며 기관 승인/실내 검증이 아니다.

공식0.9.0post1은 합성 입력에서 네이티브 종료코드3221226505로 실패해 채택하지 않았다. 동일 입력의0.8.5 실제 변환에서3층/3객체·36삼각형·경계[-16,0,-11]~[16,12,11]을 확인했다. 실제 시설 IFC·오프라인 네트워크 정책·실제 AV는 미검증이다.

## DB 버전과 복구

스키마1→2는 `asset_blobs` 비공개 바이너리 테이블을 추가한다. 메타데이터/바이트는 같은 트랜잭션으로 기록한다. 기존 JSON은 `asset_bindings=[]`, `asset_reviews=[]` 기본값으로 읽는다. 업데이트 전 WAL 일관 백업 `runtime/backups/pre-assets-v2-20261117-104936.db`를 생성했다(Git 제외).

`scripts/backup_restore.py`는 스키마1 또는1+2 백업을 해시·무결성 검사 후 존재하지 않는 새 파일로 복구하며 자산 바이트도 포함한다. 버전1 복구본은 새 서버 시작 시2로 마이그레이션한다. 다운그레이드는 자동 삭제하지 않고 서버 중지 후 구코드와 변경 전 백업을 함께 복원한다. Google Drive는 운영 DB 위치로 사용하지 않는다. PostgreSQL/기관 저장소 복구는 별도 미실행이다.
