# 역할·편성·숙지·인계 정책

## 기준

기본 역할은 지휘대장, 현장지휘, 자원지원, 통신지원, 안전관리, 상황조사, 구급지휘의 7가지다. 이는 역할 유형이며 참가 인원 상한이 아니다. 법령 기반 원본은 `/roles/templates`의 읽기전용 자료이고, 기관 편집본은 훈련별로 저장된다. 기본 임무 요약은 제공된 계획서를 바탕으로 하며 기관 SOP 승인을 뜻하지 않는다.

제16조제3항의 기본 전환 관계는 현장지휘·통신지원·안전관리·구급지휘는 현장지휘부, 자원지원은 자원지원부, 상황조사는 대응계획부다. 법령 기본 역할 ID에 모순되는 전환 부서를 지정하면 G1에서 차단한다. 지휘대장과 통제단장 관계·세부 담당반·기관의 실제 권한은 제공된 승인 편성으로 확인한다.

## 사람과 배치

- Person은 내부 가명 ID·표시명·참석 가능 여부를 가진다. 연락처·생년월일은 기본 계약에서 수집하지 않는다.
- Assignment는 역할·사람·시간대가 있는 시작/종료·근무조·현재/예정/종료·대체 순위다. 기간 겹침과 핵심 역할 공백을 검사한다.
- 발행 당시 편성은 `session.exercise.assignments`에 보존하고, 실행 중 현재 편성은 별도 `session.roster`로 관리한다.
- 게시 때뿐 아니라 시작·재개 시점에도 현재 근무기간과 편성 게이트를 재검사한다.

## 숙지

카드 버전 열람 확인 → 역할별 3개 상황형 문항 → 본인 업무 설명 → 진행자 구두 확인 기록이 필요하다. 80%는 조정 가능한 제안값이며 법정 기준이 아니다. 임무·보고선 변경 시 역할 버전이 증가하고 옛 버전 숙지는 자동 인정하지 않는다. 재응시는 이전 시도를 보존하며 구두 확인을 다시 받는다.

진단 모드는 사전 미숙지를 명시한다. 개인 연습은 실제 참석자의 숙지 승인으로 표시하지 않으며, 공동훈련 사전 승인이나 인사평정으로 자동 이전하지 않는다.

## 대체 상태기계

`PROPOSED → ACCEPTED → CARD_CHECKED → READINESS_REVIEWED → HANDOVER_COMPLETE → ACTIVE`

진행자가 사유와 가용 우선순위로 발동한다. 대체자 또는 구두 응답을 대리 기록하는 진행자가 수락·문항·설명을 기록한다. 구두 확인, 현재 상황·미확인 정보·미완료 임무·인수 확인을 마친 뒤 진행자가 활성화한다. 이미 다른 핵심 역할에 활성 배치된 사람은 자동 중복 투입하지 않는다.

활성화는 옛 배치 종료와 새 배치 시작을 같은 명령에 묶는다. 과거 메시지 수신자·조치·평가는 원 담당자 귀속을 유지한다. 현재 배치에 없는 사람의 신규 조치는 서버가 거절한다. 인계 단계와 시각·입력자·사유는 이벤트 이력에 남는다.

## 정규 운영 전 필요

소방 실무자의 법령·SOP 대조, 기관 승인 편성·보고양식·겸임 정책, 실제 근무표, 역할카드 및 대체 절차의 사용자 검수가 필요하다. 자동시험의 가상 승인 메모는 기관 승인 증거가 아니다.
