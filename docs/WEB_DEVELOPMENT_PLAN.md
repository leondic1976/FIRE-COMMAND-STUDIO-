## 우선 순서

1. 공통 데이터 계약/합성 시나리오와 런타임 경계 작성.
2. 필수 배포 선택 확인: GitHub Pages 브라우저 내부 저장 또는 서버 권한을 유지하는 웹서비스. 선택에 따라 저장/권한/외부 자료/네이티브 기능 적용표를 확정.
3. 기존 제작·장면·숙지·토론 진행·보고·인계·평가/AAR UI를 재사용하고 통신/저장·공개 투영을 새 런타임에 연결.
4. 원자 명령·단조 증가 버전/시퀀스·멱등키·실패 롤백·재접속·백업/복원·버전 마이그레이션과 정상/오류/권한 또는 공개 투영 경계/복구 시험.
5. 두 브라우저 실제 흐름·공개화면 유출 금지·키보드·모바일/대형화면·실제 주소·정적 자원 해시를 확인한 후 게시.

## 변경하지 않는 경계

실제 기관 자료/키/SOP/AV 승인·실제 성능/약10명 시범훈련을 만들어내지 않는다. 외부 API/AI/OS 도구는 기존 승인 없이 활성화하지 않는다. 브라우저 저장은 기관 서버 격리와 다르므로 이를 같은 보안 수용시험 통과로 표기하지 않는다. 명시되지 않은 유료 서비스/계정 생성은 하지 않는다.

현재 단계: web 독립 워크스페이스/공통 계약·기존 React/Three.js UI 부팅, 타입·빌드·두 브라우저 기본 검증 완료. 배포 선택 질문 답변 대기. 실행 가능한 웹판/변환된 전체 기능/배포 완료를 주장하지 않는다.
