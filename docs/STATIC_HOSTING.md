# 정적호스팅 전환과 배포

2026-11-17 사용자가 커밋/푸시/배포/정적호스팅을 명시 승인하고, 정적호스팅에서도 모든 기능이 동작하도록 개선을 요청했다. 이전의 원격 게시 금지는 이 요청 범위에서 해소됐다. 기관 정규 출시·실자료/전문가 승인은 별도다. 원본 plan.md는 변경하지 않는다.

## 현재 계약과 전환 조건

현재 웹은 같은 출처의 `/api/v1`과 `/ws/v1`을 사용하는 FastAPI·WebSocket·영구 DB 구성이다. `dist/`만 업로드하면 화면 파일은 표시되지만 로그인·작성·공동진행·권한·저장/복구는 작동하지 않는다. 이를 모든 기능이 배포된 것으로 보고하지 않는다.

| 범위 | 필요한 실행 위치/조건 |
|---|---|
| 3D/2D·지도 표시·편집 UI·카드·인쇄 | 정적 브라우저 번들. 외부 자산은 권한 확인 후 조회 |
| 로그인·기관/역할 권한·개인평가/미래 사건 격리 | 신뢰 가능한 서버 측 인증·투영. 브라우저 숨김/로컬 저장으로 대체 불가 |
| 여러 PC 공동훈련·대체/인계·서버 시퀀스·낙관적 잠금·멱등 | 공용 영구 DB와 원자 갱신·실시간 전송/재접속 실행 환경 |
| 모델/사진/영상·출처/권리·비공개 바이트 | 권한 있는 영구 객체 저장과 검사/정규화 작업. 실제 AV/호스트 승인 전 격리 |
| 외부 공공 API·지도/AI 설정 | 비밀키는 서버에만 보관. AI 기본 OFF·공식 SDK/권리 제한 유지 |
| IFC/미디어 네이티브 처리 | 기존 고정 도구/승인된 검사·격리 실행 환경. 정적 파일로 실행됐다고 주장하지 않음 |
| 백업/복구·AAR·이력 | 영구 저장소·버전 마이그레이션·실제 복원 검증 |

모든 기능과 기존 보안을 유지하려면 정적 웹에 관리형 서버리스 인증·DB·API/실시간·객체 저장·처리 실행 환경을 연결하거나, 현재 Python 서비스를 적절한 지속 실행 호스팅에 배치해야 한다. 외부 서비스 없는 브라우저 전용은 기관 간 격리/다중 PC 원자 저장 등 원본 요구와 동일하지 않다. 관리형 서버리스 사용 여부를 사전 질문했으며 답변 전 해당 필수 구조를 임의 확정하지 않는다.

## 확인한 환경과 배포 기록

- GitHub 원격: `https://github.com/leondic1976/FIRE-COMMAND-STUDIO-.git`, 공개 빈 저장소, push 권한 확인.
- 로컬 브랜치: `main`, 초기 커밋998074eacafc37cd46d98fae57e195cff7af36d4를 기록/원격 main 푸시 완료. 첫 원격 CI의 runtime 준비 오류를 수정하고 재검증한다.
- Sites 정적/Worker 호스팅 도구와 Vercel 로그인 환경은 사용 가능하다. 현재 Site 생성/배포는 수행하지 않았다. 기존 다른 Vercel 프로젝트는 변경하지 않는다.
- `.gitattributes`에서 자동 줄바꿈 변환을 끈다. Windows/Linux 간 plan/계약/소스 SHA256의 원바이트를 보존하고 Git 인덱스와 작업 파일 일치를 확인한다.
- `.env`, 키/쿠키, runtime DB/백업, node_modules, dist, 캡처/PDF/시험 임시자료는 커밋에서 제외한다. 합성 소스/가명 예시와 검토용 메타데이터만 게시한다.

기존 226개 서버·39개 웹·두 엔진13개씩/지도3개씩·60분 통과는 현재 Python 구성의 증거다. 새로운 호스팅 실행 환경은 같은 데이터 계약/권한·오류·복구·브라우저 범위를 별도로 검증해야 하며 기존 통과를 이식판의 통과로 재사용하지 않는다. 실제 배포 URL·커밋/배포 ID·검증 결과는 수행 후 기록한다.
